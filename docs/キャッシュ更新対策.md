# キャッシュ更新対策

## 変更内容

scripts/build.pyで、posts.jsとhome-selection.jsの生成後、公開HTMLのローカルJavaScript・CSS参照にファイル内容のSHA-256先頭20文字を付与します。

例: posts.js?v=cde4b1ba2b3de51f7e97

旧来の固定v=cms1等は生成時に置き換えます。同じ内容なら同じURL、内容が変わったファイルだけ新しいURLになります。index.html、archive.htmlの公開成果物に適用します。画像URL、外部のフォント、固定バージョンのSveltia CMS公式スクリプトは変更しません。

既存のGitHub ActionsはmainへのPush後にbuild.pyを実行するため、Sveltia CMSの保存にも自動適用されます。ワークフローや課金サービスの追加は不要です。ソースHTMLは変更せず、_site内の公開HTMLのみを書き換えます。

## 検証

- 自動テスト成功: 同じ内容の再ビルドでは同じHTML、記事追加でposts.jsのハッシュ変更、JS/CSS変更で各ハッシュ変更、未変更の記事データや画像URLは維持。
- ローカルHTTPサーバーとChromeの通常キャッシュで旧版を読み込んでから新版へ切り替え、通常の再読み込み（ignoreCache:false）を実行。キャッシュ削除・無効化・強制再読み込みは不使用。
- 記事数195→196を確認。変更したposts.js、archive.js、style.cssは新しいハッシュのURLでHTTP 200取得。
- 同じロゴ画像の本体を再ダウンロードしないことを確認。
- テスト用サーバーではJS/CSS/画像をmax-age=86400でキャッシュし、HTMLはno-cacheで再検証。これは新しいHTMLを取得できた場合の動作検証であり、GitHub PagesのHTTPヘッダーを変更したわけではありません。
- 既存195記事の公開データ、トップ各5本、CMSのindex.html/config.ymlは変更前と一致。テスト投稿は隔離環境のみ。本番データには追加していません。

## 残る制約

- HTML自体がブラウザーやCDNから古い状態で返る間は、古いハッシュが参照される場合があります。本対策は新しいHTMLの取得を保証するものではありません。
- 開いたままのページや戻る操作で復元された画面を自動更新する機能はありません。通常の再読み込みが必要です。
- GitHub Pagesへの配信完了とCDNへの反映には時間差が生じ得ます。今回Pages側のHTTPキャッシュ設定・外部CDNは変更していません。
- 画像を同じURLのまま差し替えた場合は、画像キャッシュが残り得ます。画像更新は別名でアップロードする運用が適しています。
- CMS本体は既存の固定バージョンを維持。CMS設定ファイルのキャッシュ制御は今回のJS/CSS対策の対象外です。
- Commit・Pushは未実施。公開サイトへの適用確認はPush後になります。

変更ファイル: scripts/build.py、scripts/test_build.py、本説明書。
